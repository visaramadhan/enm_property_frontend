==============================================================================
1. ARSITEKTUR KOMPONEN & PRINSIP KODE
==============================================================================

Tujuan: setiap pola UI didefinisikan SEKALI, dipakai berkali-kali.
"OOP" di UI = enkapsulasi + komposisi (bukan pewarisan berlapis).

1.1 Lapisan (dependensi satu arah ke bawah)

  app/        route & halaman (menyusun feature + shell)
    -> features/   logika domain (listing, auth, checkout, profil)
      -> patterns/ komposit lintas-fitur (StatusScreen, PageHeading, Shell)
        -> ui/     atom & molekul murni (Button, Field, Badge, Card, ...)
          -> tokens/  CSS variables (warna, radius, shadow, tipografi)

  lib/ (format.ts: rupiah, tanggal) dipakai semua lapisan, tanpa UI.
  Aturan: lapisan bawah TIDAK boleh mengimpor lapisan atas.

1.2 Pemetaan prinsip -> aturan konkret di sistem ini

  KISS      Satu komponen = satu tugas jelas. Varian secukupnya
            (primary, secondary, outline, quiet) - tidak ada varian
            "jaga-jaga".
  YAGNI     Hanya bangun yang SUDAH muncul di layar Figma. Pola yang baru
            muncul 1x (Stepper, Segmented, Switch, UploadZone, Pagination)
            tetap lokal di fitur pemakainya. Komponen situs referensi
            (marquee, testimonial, FAQ, dll) ada di Backlog, tidak dibuat.
  WET       (Write Everything Twice) Toleransi duplikasi sekali;
            abstraksikan saat salinan ke-2/ke-3 muncul (Rule of Three).
            Tabel keputusan di 1.3. Token tetap DRY: nilai warna/radius
            hanya ditulis di tokens/.
  SoC       Pisahkan: tampilan (ui/), komposisi (patterns/), domain
            (features/), data/format (lib/, hooks). Komponen UI tidak
            memanggil API.
  SRP       Satu alasan berubah per komponen. Button hanya merender tombol;
            PropertyTable hanya merender baris; format rupiah ada di lib/.
  OCP       Tambah varian/kolom/status = tambah ENTRI KONFIG, bukan
            mengubah logika komponen (lihat StatusBadge & DataTable).
  LSP       Semua varian Button (dan LinkButton) memakai kontrak props yang
            sama sehingga dapat saling menggantikan tanpa merusak layout.
  ISP       Props kecil dan spesifik (Labelled, WithHint, WithError) -
            jangan satu FieldProps raksasa yang dipaksakan ke semua.
  DIP       Komponen UI bergantung pada ABSTRAKSI (peta status, kolom,
            token), bukan pada data domain. Domain "ListingStatus" meng-
            injeksi konfigurasinya ke StatusBadge.
  Clean Code Nama jelas (BEM/PascalCase), fungsi kecil, tanpa angka ajaib
            (pakai token), tanpa komentar yang mengulang kode.
  Boy Scout Setiap menyentuh layar/komponen, rapikan sedikit: gabungkan
            hex mirip, hapus artefak Figma, naikkan teks <10px.
  Refactoring Lakukan bertahap dengan tabel konsolidasi (2.3, 5.2) sebagai
            checklist; satu PR = satu jenis perapian.

  // Varian = data. Menambah varian = menambah satu entri CSS (.btn--x),
  // tipe ikut berubah di sini saja.
  export type ButtonVariant = 'primary' | 'secondary' | 'outline' | 'quiet';
  export type Size = 'sm' | 'md' | 'lg';

  // ISP: kontrak visual kecil, dipakai Button DAN LinkButton (LSP)
  export interface ButtonLook {
    variant?: ButtonVariant;
    size?: Size;
    fullWidth?: boolean;
    trailing?: 'arrow';
  }

  export function Button({ variant='primary', size='md', fullWidth, trailing,
                           children, ...rest }: ButtonLook & ButtonHTMLAttributes<HTMLButtonElement>) {
    return (
      <button className={cx('btn', `btn--${variant}`, `btn--${size}`, fullWidth && 'btn--block')} {...rest}>
        {children}{trailing === 'arrow' && <span aria-hidden>→</span>}
      </button>
    );
  }

9.3 ui/StatusBadge  (DIP + OCP: UI tidak tahu domain)

  export type Tone = 'success' | 'neutral' | 'warning' | 'danger';
  export interface StatusDef { label: string; tone: Tone }
  export type StatusMap<K extends string> = Record<K, StatusDef>;

  export function StatusBadge<K extends string>({ status, map }: { status: K; map: StatusMap<K> }) {
    const { label, tone } = map[status];
    return <span className={cx('badge', `badge--${tone}`)}><i className="badge__dot" />{label}</span>;
  }
